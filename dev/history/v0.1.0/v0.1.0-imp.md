# v0.1.0 移植報告

移植元は DesktopAgent `f45d293`。バージョン別の Release 実行先は `C:/develop/EchoType/release/v0.1.0/EchoType.App.exe`。

- [x] 専用音声入力を独立 WPF アプリに分離。ホットキー、途中・確定認識、比較、整形と決定、キュー、セッション内の未送信履歴、個人辞書、アプリ別設定を移植。
- [x] 入力先のフォーカス監視と UIA の制約を維持。ライブキャプション UIA は DesktopAgent と同じユーザー別 mutex を使う。Windows セッションロック時は録音を破棄し、進行中の処理を取り消して入力先を解除する。
- [x] 同一アカウントで旧 DPAPI ストアから対象データだけを一度移す CLI を追加。旧 SQLite は読み取り専用、移行先は `%LOCALAPPDATA%/EchoType/data/echo.sqlite`。元チャットの実行結果は共通設定 1、音声入力設定 1、アプリ別設定 0、個人辞書 0。
- [x] 本体、字幕 UIA、Windows AI 音声、字幕 DLL 補助をビルド。合成データの契約試験 32 件、非表示デスクトップでのアプリ起動、ロック状態の模擬切替、録音キュー、フォーカス監視を確認。
- [x] DevLauncher 原本と共通台帳へ登録。GitHub の EchoType リポジトリを非公開で作成。

旧版の未送信履歴はメモリのみで移行対象の保存レコードはない。EchoType の未送信履歴も実行中のみ利用可能。旧モデルを読み込む場合は起動時の `--model-root` に旧 `DesktopAgent/model` を指定する。Haas は既存の共通パスを参照する。

Release 版の実マイク、個々のモデルによる実音声認識と Codex CLI の実通信、実アプリへの書き込み、Windows の実ロック通知と同時字幕利用は切替後の確認項目。手順と引き継ぎ先は [利用手順](../../../README.md) と [切替後の確認](../../NEXT_STEPS.md)。

## 2026年11月15日 ASR依存のセキュリティ保守

Whisper用の `requirements.txt` で filelock を 4.0.1 から 4.2.10 に更新した。旧版が対象となる Windows のロック関連公告を確認し、4.2.10 への OSV のバージョン照会では該当公告が返らなかった。 [filelock公式公告](https://github.com/tox-dev/filelock/security/advisories) [PyPIの配布版](https://pypi.org/project/filelock/4.2.10/)

Windows x64のPython 3.14.7で独立したvenvを作成し、依存導入と `pip check`、固定リビジョンの Whisper base モデルの取得、ワーカーの起動、合成した日本語音声の認識、ロード済みモデルの再利用、標準入力を閉じた後の正常終了を確認した。同梱の契約試験は32件成功した。検証機のGPUはIntel UHD Graphics 770で、CTranslate2が検出したCUDAデバイスは0件だった。Whisper用CUDAの定義は独立しており、CUDAでの推論は未確認。

### Qwenの利用構成と保留候補

Qwenの3モデルは選択式で `qwen-venv` を共有し、Whisperと高速ASRは別のvenvを使用する。Qwenの標準セットアップは公式CPU版PyTorchを取得する。CUDAでQwenを動かすには別途CUDA対応のPyTorchが必要で、Whisper用のcuBLAS導入はQwenへ適用されない。推論ワーカーはモデルの固定リビジョンとローカルのsafetensorsを使う。Qwen側のGradioデモとFlaskのWebサーバーを起動する入口はEchoTypeにない。BrotliはGradioの依存であり、HTTPクライアントの圧縮応答にも使われ得る。

Qwen用の `requirements-qwen.txt` で Brotli 1.2.1、Werkzeug 3.1.9、msgpack 1.2.3を採用した。Windows x64のPython 3.14.7でPyPIとPyTorch公式配布元から隔離venvへ依存を導入し、`pip check` と各パッケージの通常処理を確認した。固定リビジョンのQwen3-ASR-0.6Bを取得し、CPUでのワーカー起動、日本語合成音声の認識、モデルの再利用、標準入力を閉じた後の正常終了を確認した。Qwenの1.7B系とCUDAでの推論は未確認。 [BrotliのJVN公告](https://jvn.jp/vu/JVNVU97400824/index.html) [Werkzeugの公式公告](https://github.com/pallets/werkzeug/security/advisories/GHSA-g6x2-hccm-hh4m) [msgpackの公式リリース](https://github.com/msgpack/msgpack-python/releases/tag/v1.2.3)
